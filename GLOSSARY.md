# Glossary

This glossary collects abbreviations and concepts found in root-level `L*.md` files in `_agent/references/`.

| Term | Description | Related references |
|---|---|---|
| Action-capable agent | An agent that can do something through tools, not only write an answer. For example, it may send a message, change a file, or call an API, so it needs extra safety checks. | [L7: external context safety and RAG risks](./_agent/references/L7_external_context_safety_and_rag_risks.md) |
| Adversarial content | Content that tries to confuse the agent or change what it is supposed to do. Treat it as ordinary data, not as instructions to follow. | [L2: execution guards and instruction data separation](./_agent/references/L2_execution_guards_and_instruction_data_separation.md) |
| Adversarial input | Input created to bypass rules, leak data, or make the system do something unsafe. The system should check it before using it in tools or decisions. | [L2: prompt injection and validation](./_agent/references/L2_prompt_injection_and_validation.md) |
| Agent | A system where a model can choose steps or tools to reach a goal. It is more flexible than a fixed workflow, but also needs clearer limits. | [L4: image recognition and generation agents](./_agent/references/L4_image_recognition_and_generation_agents.md) |
| Agent configuration | The settings that describe what an agent may do: instructions, tools, context, and limits. Clear configuration makes the agent easier to test and debug. | [L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md) |
| Agent loop | A repeated cycle where the model checks the situation, uses a tool, looks at the result, and decides what to do next. This is useful when the next step is not known upfront. | [L3: MCP architecture and transport selection](./_agent/references/L3_mcp_architecture_and_transport_selection.md)<br>[L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md) |
| Agent workflow | A workflow where the model helps decide steps, tools, and the final answer. Use it when simple fixed code cannot easily cover all cases. | [L2: workflow orchestration and reflection](./_agent/references/L2_workflow_orchestration_and_reflection.md) |
| Agentic RAG | Retrieval-Augmented Generation done as a search loop. The agent searches, reads results, improves the query, checks if it has enough evidence, and then answers. | [L6: agentic RAG and context gathering](./_agent/references/L6_agentic_rag_and_context_gathering.md) |
| AI | Artificial Intelligence. In this glossary it usually means software behavior powered by models, such as LLMs, agents, or image/audio/video models. | [L3: API constraint audit and tool wrapping](./_agent/references/L3_api_constraint_audit_and_tool_wrapping.md)<br>[L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md)<br>[L5: production risk controls](./_agent/references/L5_production_risk_controls.md)<br>[L6: dynamic context engineering](./_agent/references/L6_dynamic_context_engineering.md)<br>[L7: external context safety and RAG risks](./_agent/references/L7_external_context_safety_and_rag_risks.md) |
| AI-assisted deployment safety | Rules for using AI help during deployment without blindly trusting it. The human or deterministic code should still control secrets, infrastructure, and risky changes. | [L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md) |
| AI-friendly API | An API that is easy for a model to choose and call correctly. It should have clear names, clear inputs, clear outputs, and useful error messages. | [L3: API constraint audit and tool wrapping](./_agent/references/L3_api_constraint_audit_and_tool_wrapping.md) |
| API | Application Programming Interface. A contract that tells software how to ask another system or component to do something. | [L1: prompt design](./_agent/references/L1_prompt_design.md)<br>[L2: security permissions and exposure](./_agent/references/L2_security_permissions_and_exposure.md)<br>[L3: API constraint audit and tool wrapping](./_agent/references/L3_api_constraint_audit_and_tool_wrapping.md)<br>[L3: safe write and native MCP integration](./_agent/references/L3_safe_write_and_native_mcp_integration.md)<br>[L3: spec driven MCP server build](./_agent/references/L3_spec_driven_mcp_server_build.md)<br>[L3: tool family and response contracts](./_agent/references/L3_tool_family_and_response_contracts.md)<br>[L4: audio agent workflows](./_agent/references/L4_audio_agent_workflows.md)<br>[L4: multimodal model selection and attachments](./_agent/references/L4_multimodal_model_selection_and_attachments.md)<br>[L4: video agent workflows](./_agent/references/L4_video_agent_workflows.md)<br>[L5: performance cost and rate limits](./_agent/references/L5_performance_cost_and_rate_limits.md)<br>[L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md)<br>[L5: production risk controls](./_agent/references/L5_production_risk_controls.md)<br>[L6: attention and context control techniques](./_agent/references/L6_attention_and_context_control_techniques.md)<br>[L7: search architecture and embedding models](./_agent/references/L7_search_architecture_and_embedding_models.md) |
| API constraint audit | A review of an API before exposing it to a model. The goal is to find confusing parts, risky actions, missing limits, or places where a wrapper is needed. | [L3: API constraint audit and tool wrapping](./_agent/references/L3_api_constraint_audit_and_tool_wrapping.md) |
| API rate limit | Application Programming Interface rate limit. A limit on how many requests or tokens can be used in a period of time. | [L5: performance cost and rate limits](./_agent/references/L5_performance_cost_and_rate_limits.md) |
| Application-induced model error | A model mistake caused by the application setup, not only by the model itself. Examples include missing tools, wrong instructions, or bad context. | [L5: model failure modes and validation](./_agent/references/L5_model_failure_modes_and_validation.md) |
| Attachment | A file or media item included in a request, such as an image, audio file, video, PDF, or document. The system must know whether the model should inspect it or a tool should use it. | [L4: multimodal model selection and attachments](./_agent/references/L4_multimodal_model_selection_and_attachments.md) |
| Augmented function calling | Giving the model extra useful context before it calls a function or tool. This helps it choose better arguments. | [L2: query transformation context and optimization](./_agent/references/L2_query_transformation_context_and_optimization.md) |
| Batching | Combining several related operations into one larger operation. This can save time and reduce repeated tool calls. | [L2: query transformation context and optimization](./_agent/references/L2_query_transformation_context_and_optimization.md) |
| Caching | Saving a result so the system can reuse it later instead of doing the same expensive work again. It is useful when the same input should produce the same result. | [L2: query transformation context and optimization](./_agent/references/L2_query_transformation_context_and_optimization.md) |
| Checksum guard | A safety check that notices when a file changed since it was last read. It helps avoid overwriting someone else's newer changes. | [L3: safe write and native MCP integration](./_agent/references/L3_safe_write_and_native_mcp_integration.md) |
| Chunk | A smaller piece of a larger document. Search systems often use chunks because they are easier to find, rank, and place into model context. | [L7: indexing chunking and document representation](./_agent/references/L7_indexing_chunking_and_document_representation.md) |
| Chunking strategy | The rule for splitting documents into chunks. A good strategy keeps chunks small enough to search, but large enough to keep useful meaning. | [L7: indexing chunking and document representation](./_agent/references/L7_indexing_chunking_and_document_representation.md) |
| Classification | Assigning input to one of several predefined categories. For example, classifying a message as `question`, `bug`, or `feedback`. | [L1: task decomposition and pipeline design](./_agent/references/L1_task_decomposition_and_pipeline_design.md) |
| Classification prompt | A prompt that asks the model to choose from predefined categories. The allowed categories should be listed clearly. | [L1: prompt design](./_agent/references/L1_prompt_design.md) |
| CLI | Command Line Interface. A way to use a program by typing commands in a terminal. | [L3: local stdio and mcpb distribution](./_agent/references/L3_local_stdio_and_mcpb_distribution.md)<br>[L3: MCP architecture and transport selection](./_agent/references/L3_mcp_architecture_and_transport_selection.md)<br>[L7: hybrid retrieval and RAG effectiveness](./_agent/references/L7_hybrid_retrieval_and_rag_effectiveness.md)<br>[L7: indexing chunking and document representation](./_agent/references/L7_indexing_chunking_and_document_representation.md)<br>[L7: search architecture and embedding models](./_agent/references/L7_search_architecture_and_embedding_models.md) |
| Cloudflare Workers deployment | Running and publishing code through Cloudflare's serverless platform. In these notes, it is one possible way to publish a remote MCP server. | [L3: remote MCP publication](./_agent/references/L3_remote_mcp_publication.md) |
| Confirmation | A clear approval step before or after a risky action. The user should see what will happen before approving it. | [L5: production risk controls](./_agent/references/L5_production_risk_controls.md) |
| Confirmation step | A required user approval before a destructive or high-risk action. It is a guardrail for actions that affect data, money, people, or external systems. | [L2: execution guards and instruction data separation](./_agent/references/L2_execution_guards_and_instruction_data_separation.md) |
| Context assembly | The process of building what the model sees before it answers. It may include instructions, user input, files, tool results, and stored state. | [L5: production agent architecture and deployment](./_agent/references/L5_production_agent_architecture_and_deployment.md) |
| Context management | Choosing and organizing only the information the model needs for the current task. Good context is short enough to avoid noise but complete enough to answer well. | [L2: context routing and tool exposure](./_agent/references/L2_context_routing_and_tool_exposure.md) |
| Context selection | Picking the most relevant messages, files, tool results, or facts for the model. It helps reduce confusion and unnecessary exposure of data. | [L2: context routing and tool exposure](./_agent/references/L2_context_routing_and_tool_exposure.md) |
| Context window | The maximum amount of text and output a model can handle in one request. If the input is too large, the model may have less space for the answer. | [L5: performance cost and rate limits](./_agent/references/L5_performance_cost_and_rate_limits.md) |
| Control | A product or code rule that keeps important actions under user or system control. Use controls when model judgment alone is not safe enough. | [L5: production risk controls](./_agent/references/L5_production_risk_controls.md) |
| Conversation summarization | Replacing old conversation history with a shorter summary. This keeps important facts while reducing context size. | [L2: context routing and tool exposure](./_agent/references/L2_context_routing_and_tool_exposure.md) |
| Cosine similarity | A way to compare two vectors and estimate how similar they are. In search, it can suggest useful results, but it does not prove that a result is correct. | [L7: search architecture and embedding models](./_agent/references/L7_search_architecture_and_embedding_models.md) |
| Data exposure review | A check of what data the agent can access. The goal is to give access only to what the task really needs. | [L2: security permissions and exposure](./_agent/references/L2_security_permissions_and_exposure.md) |
| Data movement | Moving information from one place to another, such as from a file into an email. This can be risky if private data goes to the wrong destination. | [L5: production risk controls](./_agent/references/L5_production_risk_controls.md) |
| Decomposed processing | Splitting one media task into smaller steps. For video, this may mean extracting audio, transcribing speech, and checking frames separately. | [L4: video agent workflows](./_agent/references/L4_video_agent_workflows.md) |
| Defense in depth | Using several safety layers instead of relying on one rule. If one layer fails, another may still protect the system. | [L2: sandboxing monitoring and audit](./_agent/references/L2_sandboxing_monitoring_and_audit.md) |
| Destructive action | An action that can delete, overwrite, or permanently change data. It should usually require preview, confirmation, or another safety check. | [L3: safe write and native MCP integration](./_agent/references/L3_safe_write_and_native_mcp_integration.md) |
| Deterministic workflow | A workflow where code decides the steps in advance. This is best when the process is known and does not need model decisions at each step. | [L2: workflow orchestration and reflection](./_agent/references/L2_workflow_orchestration_and_reflection.md) |
| Direct audio understanding | Giving audio directly to a model that can understand sound or speech. This can preserve tone or sound details that plain transcription may miss. | [L4: audio agent workflows](./_agent/references/L4_audio_agent_workflows.md) |
| Direct video analysis | Giving a video directly to a model or API that can inspect it. This is simpler than splitting the video into audio and frames, if the tool supports it. | [L4: video agent workflows](./_agent/references/L4_video_agent_workflows.md) |
| Document representation | The form of a document used by the model or search system. It can be plain text, OCR text, page images, metadata, summaries, or a mix of these. | [L7: indexing chunking and document representation](./_agent/references/L7_indexing_chunking_and_document_representation.md) |
| Document template | A reusable starting file for creating a document. It helps keep generated documents consistent. | [L4: rendered documents and PDF workflows](./_agent/references/L4_rendered_documents_and_pdf_workflows.md) |
| DOCX | Office Open XML Document. A Microsoft Word-style document file that may need parsing before a model or search system can use it well. | [L7: external context safety and RAG risks](./_agent/references/L7_external_context_safety_and_rag_risks.md)<br>[L7: indexing chunking and document representation](./_agent/references/L7_indexing_chunking_and_document_representation.md)<br>[L7: search architecture and embedding models](./_agent/references/L7_search_architecture_and_embedding_models.md) |
| Downstream use | Anything that happens later based on model output. If code, tools, storage, or the UI uses the output, that output needs stronger checks. | [L1: structured outputs and validation](./_agent/references/L1_structured_outputs_and_validation.md)<br>[L1: task decomposition and pipeline design](./_agent/references/L1_task_decomposition_and_pipeline_design.md) |
| Dry run | A preview of an action without actually changing anything. It lets you inspect what would happen before committing the action. | [L3: safe write and native MCP integration](./_agent/references/L3_safe_write_and_native_mcp_integration.md) |
| Dynamic context engineering | Choosing where information should live: in the prompt, in files, in state, in tools, or in code. The goal is to give the model the right information without overloading it. | [L6: dynamic context engineering](./_agent/references/L6_dynamic_context_engineering.md) |
| Dynamic knowledge resources | A task-specific set of documents or data sources shown to the model. This avoids giving the model too much unrelated knowledge. | [L2: context routing and tool exposure](./_agent/references/L2_context_routing_and_tool_exposure.md) |
| Dynamic tool discovery | Finding or enabling only the tools that matter for the current task. This helps the model avoid choosing from too many tools. | [L3: MCP security scaling and OAuth](./_agent/references/L3_mcp_security_scaling_and_oauth.md) |
| Dynamic tool list | A task-specific list of tools available to the model. A shorter, relevant list makes tool choice safer and easier. | [L2: context routing and tool exposure](./_agent/references/L2_context_routing_and_tool_exposure.md) |
| Dynamic workflow | A workflow where the model can decide the next step after seeing intermediate results. Use it when the path depends on what the system discovers. | [L2: workflow orchestration and reflection](./_agent/references/L2_workflow_orchestration_and_reflection.md) |
| Embedding | A list of numbers that represents the meaning of text, an image, or other content. Search systems compare these number lists to find items with similar meaning. | [L7: search architecture and embedding models](./_agent/references/L7_search_architecture_and_embedding_models.md) |
| End frame | An image used as the desired final frame of a generated video. It helps guide where the video should end. | [L4: video agent workflows](./_agent/references/L4_video_agent_workflows.md) |
| Evaluation | Checking whether something is correct, good enough, safe, or complete. It can be done by code, a model, or both. | [L1: task decomposition and pipeline design](./_agent/references/L1_task_decomposition_and_pipeline_design.md) |
| Evaluation prompt | A prompt that asks the model to judge quality, correctness, safety, or completion. It should say exactly what criteria to use. | [L1: prompt design](./_agent/references/L1_prompt_design.md) |
| Execution guard | A check that happens before the system performs an action. It can verify required inputs, permissions, confirmations, or safe routing. | [L2: execution guards and instruction data separation](./_agent/references/L2_execution_guards_and_instruction_data_separation.md) |
| Exposure surface | Everything the agent can reach: tools, data, permissions, and actions. A smaller exposure surface usually means lower risk. | [L2: security permissions and exposure](./_agent/references/L2_security_permissions_and_exposure.md) |
| External context | Information loaded from outside the model, such as files, tool results, search results, messages, or attachments. | Extraction | Pulling specific facts from messy or unstructured input. For example, extracting name, date, and address from an email. | [L1: task decomposition and pipeline design](./_agent/references/L1_task_decomposition_and_pipeline_design.md) |
| Extraction prompt | A prompt that asks the model to pull specific facts from text or media. It should name the fields the model must return. | [L1: prompt design](./_agent/references/L1_prompt_design.md) |
